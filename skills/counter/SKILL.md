# @samline/counter

Build against the installed version; this skill describes 1.8.0.

- **Install:** `npm install @samline/counter`. Plain HTML: load `https://cdn.jsdelivr.net/npm/@samline/counter@1.8.0/dist/browser/counter.global.js`; it counts every `[data-counter]` on its own (`data-manual` on the script tag, then `Counter.auto(options)`, to pass options). No stylesheet.
- **Markup first:** render the final value and put the plain number in the attribute: `<span data-counter="12480">12,480</span>`. Empty `data-counter` reads the text in the element's `lang`. Also `data-counter-from` (higher counts down), `-duration`, `-delay` (ms), `-easing` (`linear`, `ease-in`, `ease-out`, `ease-in-out`, `ease-out-expo`, `ease-out-back`, or `cubic-bezier(x1, y1, x2, y2)` 1.5.0+), `-speed` (units per second instead of duration; 1.5.0+), `-decimals`, `-locale`, `-repeat`, `-start` (`visible`, `load`, `manual`; 1.1.0+), `-grouping` (`auto`, `true`, `false`; 1.1.0+), `-as` (`number`, `time`, `date`; 1.2.0+), `-step`, `-date-style` (1.2.0+), `-live` (1.3.0+, on by default), `-css-vars` (present or a closest-ancestor selector) and `-output` (selector; 1.4.0+), `-steady` (1.6.0+), `-roll` (odometer columns; 1.9.0+), `-label` (`false` to opt out), `-announce` (present or a `{value}` template) and `-reduced-motion` (`final`, `count`) (1.7.0+). `data-counter-stagger="150"` on a container staggers its numbers (1.5.0+). Attributes win over options.
- **Script:** `autoCounter(options)` for a whole page (also picks up elements added later; returns `{ refresh, destroy }`), or `const c = counter(target, { from, to, duration, speed, delay, stagger, easing, decimals, locale, format, formatter, repeat, start, grouping, as, step, dateFormat, live, cssVars, output, steady, roll, label, announce, reducedMotion, root, rootMargin, threshold, onStart, onUpdate, onComplete })`.
- **Outputs (1.4.0+):** `data-counter-output="#bar"` writes the value to `<progress>`, `<meter>` or inputs (`value`), other elements get `aria-valuenow`; `output` may be a function `(value, element, progress) => {}`. `data-counter-css-vars` (or `cssVars: true | '.card'`) sets `--counter-value` and `--counter-progress` (0–1) on the element or its closest match. Give the CSS a no-JS default (`--counter-value: 86`) and keep final values in `<progress value>`. `destroy()` removes the variables and restores outputs.
- **Live numbers (1.3.0+):** `c.set(value, el?)` counts from the value on screen to `value` (new final value; no delay), `c.increment(by = 1, el?)` / `c.decrement(by, el?)` add to the final value so quick clicks add up. Changing `data-counter` (or `datetime` with `as="date"`) counts to it automatically unless `data-counter-live="false"` / `live: false`; prefer updating the attribute from server-rendered or framework code over re-creating counters. `animateNumber()` returns a callable cancel with `pause`, `resume`, `retarget(to, duration?)`, `getValue`, `isRunning`. With the CDN bundle, call `Counter.auto()` before `Counter.getCounter()` in a script that runs before the DOM is ready.
- **Controller (1.1.0+):** `c.start(el?)`, `pause`, `resume`, `reset` (shows `from`, then call `start()`), `finish`, `update(options)`, `refresh()` (re-reads attributes), `getSnapshot()` (`{ element, value, state, from, to, progress }[]`), `format(value, el?)` (the text the counter shows for a value; 1.6.0+), `c.on('start'|'update'|'pause'|'resume'|'reset'|'complete', ({ element, value, state }) => {})` returns an unsubscribe. `c()` or `c.destroy()` restores the original markup (1.0's `stop()` still works). Bubbling DOM events `counter:start`, `counter:pause`, `counter:resume`, `counter:reset`, `counter:complete` (not `update`). `getCounter(element)` returns the controller of an element `autoCounter` or the CDN bundle started. One controller per element: calling `counter` again returns the existing one.
- **Formatting:** `format` takes `Intl.NumberFormat` options (currency, compact, unit). Percent: write fractions (`0.25`). Since 1.1.0 the rendered text is the template: grouping copies the HTML by default (`8000` stays `8000`); `grouping: true` / `data-counter-grouping="true"` groups a raw backend `8000` as `8,000`, `false` never groups (years, IDs). Prefix and suffix (`$`, ` visits`) stay, also with `format`, unless `format.style` is currency/percent/unit; `formatter` replaces the text. The count ends on the original markup when it reads like the final value. Before 1.1.0, keep units, `+` and `%` outside the element. Use `font-variant-numeric: tabular-nums`, or `steady` / `data-counter-steady` (1.6.0+: tabular digits plus the width of the wider of start and final text reserved, restored on destroy). Since 1.6.0, text in non-Latin decimal digits (`١٬٢٣٤`, `१,२३४`) is read and counts in the same digits; Latin stays Latin; `format: { numberingSystem }` overrides. Clocks and dates (1.2.0+): `<time data-counter data-counter-as="time">23:59:59</time>` counts seconds in the text's pattern (`h:mm:ss` or `m:ss`, `data-counter-from` may be a clock); `<time data-counter data-counter-as="date" datetime="2026-12-31">December 31, 2026</time>` counts days from January 1 (or `data-counter-from`, ISO) with `Intl.DateTimeFormat`; `data-counter-step` in units, seconds or days. With `time`, values are seconds; with `date`, timestamps in ms. Other units: `formatter`. Simulated: they run for `duration`, not on the wall clock.
- **Roll (1.9.0+):** `roll` / `data-counter-roll` renders each digit as a column turning `value / 10^place` (inline styles, digits run in an LTR isolate, fast columns snap to whole digits) and ends on the original markup. Needs text whose digits equal the value (`1,250`, `$12.50`, `99.95%`); clocks, dates, compact and negatives count as text. Combine with `steady` to keep leading places' width. During roll, `textContent` is not the number: read values from events or `getSnapshot()`.
- **Lite (1.8.0+):** `@samline/counter/lite` and `dist/browser/counter-lite.global.js` (also `window.Counter`; load one bundle, not both): same API for plain numbers, about 6 KB gzip instead of 9 KB. Leaves out `as: 'time' | 'date'` (those elements stay as rendered), `cssVars`, `output`, `steady`, `roll` and `announce`. Suggest it when the page only counts numbers.
- **Without DOM:** `animateNumber({ from, to, duration, easing, onUpdate, onComplete })` returns a cancel function; `cubicBezier(string)` and `isEasing(value)` (1.5.0+); `parseNumber(text, locale)` (any script's digits since 1.6.0), `digitValue(char)`, `numberingSystem(zero)` (1.6.0+).
- **Semantics:** starts when half the number is visible; states `pending`, `counting`, `paused` (1.1.0+), `done` in `data-counter-state`; reduced motion keeps the rendered value (`reducedMotion: 'count'` counts anyway; 1.7.0+). Since 1.7.0, while not `done`, generic elements (`span`, `strong`, `data`, `time`, `div`…) without their own role or label get `role="img"` and `aria-label` with the final text, removed when done and on destroy. `announce` adds one shared polite live region (`[data-counter-announcer]`) and reads new values from `set`/`increment`/`decrement`/live attributes, never the first count.
- **Do not** leave the element empty in the HTML, count with `setInterval`, or call `counter` on elements `autoCounter` already handles.
